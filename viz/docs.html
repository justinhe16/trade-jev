What it is

The live runner streams NQ's top-10 order book from Databento and asks Jev every 15 seconds for BUY, SELL or HOLD. It applies the same filters as the backtest (0.7 cutoff, 4 agreeing answers, 30s minimum hold, 200-tick stop, 100-tick target) and keeps a paper position with the backtest's fills and costs. The Live tab shows the signal, so you can trade it by hand.

It places no orders. It runs the backtest code on a growing order book, and a parity check confirms that a recorded day streamed through it gives exactly the backtest's trades (15 days × 3 settings, every trade identical).

This is a lead, not a proven edge. The filter settings were picked from 1,920 tried on the same 15 days they were scored on. In the 11-day holdout run (looser settings), Jev made +$14.3k on its second half against +$11.4k for random trades, with a $27.7k max drawdown. Forward-test on new days with the settings frozen before risking money.

Use cases

Primary · unattended

1. Forward test

Run every regular session with settings frozen. Each day becomes an out-of-sample result with its own random and imbalance baselines, decided on the same clock.

uv run python -m trade_jev.live --no-open
You at the screen

2. Manual signal trading

Keep Live open with alerts on. When the banner changes (ENTER LONG, REVERSE TO SHORT…), enter at your broker with a bracket order at the stop and target prices shown. Exits then happen without you. Log each fill in “My fills” to measure slippage against the paper fill.

uv run python -m trade_jev.live
After the close

3. Post-session review

Each session is saved as a normal run (runs/live-<day>) and a normal day file (data/live/), so it opens in Replay and works with the sweep scripts. Treat setting sweeps as research, never as changes to the live settings.

uv run python -m trade_jev.view
uv run python scripts/replay_sweep.py runs/live-2026-10-05
No subscription needed

4. Rehearsal

Play a recorded day through the live engine at any speed: real Jev calls, or a run's stored answers for free. Good for learning the screen and for testing changes outside market hours.

uv run python -m trade_jev.live --from-file 2026-06-23 --speed 60 \
  --stored-answers runs/20260917-172739
Before trusting changes

5. Parity check

Confirms the live engine and the backtest give identical trades on every recorded day. Run it after any change to the engine, harness or filters.

uv run python scripts/check_live_parity.py runs/20260917-172739 \
  runs/20260917-174009 runs/20260917-holdout11

How to run

It's a local server on http://localhost:8765. One command starts the feed, Jev, the paper trading and the web app (Replay, Live and Docs). Nothing listens outside your machine.

One-time setup

uv sync
echo "TYPESAFE_API_KEY=..."  >> .env
echo "DATABENTO_API_KEY=..." >> .env      # live only; rehearsals don't need it

Each trading day

uv run python -m trade_jev.live           # start any time before 09:30 ET; opens /live
# Ctrl-C to stop. At 15:55 ET it flattens, writes the run, and keeps the page up.

Started late? It replays the session so far from Databento (intraday replay), so the look-backs and the 4-answer streak are right. Old signals show as CATCH-UP and never alert. Add --no-catch-up to skip the replay.

Automation (executor)

The executor places the live runner's signals at a broker. The live runner sends an intent (be long / short / flat, with a sequence number and the current quote) to localhost:8766 the moment Jev's answer passes the filters. The executor compares it with the real position, acts only on the difference, and reports fills back to the Live page. It always starts disarmed; you arm it with the button on the Executor card.

# terminal 1: executor (fake broker for rehearsals; a real broker backend is private, see below)
uv run python -m trade_jev.executor --broker fake --allow-replay
# terminal 2: live runner, sending intents to it
uv run python -m trade_jev.live --from-file 2026-06-23 --speed 60 \
  --stored-answers runs/20260917-172739 --exec-url http://127.0.0.1:8766
# then open /live and press Arm
RuleWhat the executor does
New signalActs only when the paper position changes (a new sequence number). Flat → enter; opposite side → flatten, check it's flat, then enter. Never more than 1 contract.
Entry orderMarketable limit: ask + 2 ticks to buy, bid − 2 ticks to sell (--slip-ticks), with a broker-side bracket for the 200-tick stop and 100-tick target.
Broker exited firstIf the broker's stop or target filled while paper is still in the trade, it stays flat and shows an alert. It never re-enters on its own.
Paper flat, real position openFlattens. Note: arming while you hold a position the paper doesn't flattens it.
RefusesDisarmed, catch-up signals, intents older than 5s, replay intents (unless --allow-replay), and entries outside 09:30–15:55 ET. Exits are always allowed.
Daily loss −$2,000Flattens and halts for the rest of the day (--max-daily-loss). Can't be cleared that day.
40 entries a dayHalts new entries (--max-orders). Flattens don't count.
ErrorsA failed order, a position that doesn't match after an action, or no heartbeat from the live runner for 15s (flattens if in a position): halts. Disarm, then arm again to resume.
Auto-disarmThe live runner disarms when the session closes, the feed goes stale, or the executor stops reporting for 10s.

Every intent, decision, broker action and latency is logged to runs/executor/<day>.jsonl. Real broker backends are not part of this repo: --broker NAME loads private/NAME.py (gitignored), which implements the small broker interface in src/trade_jev/executor/broker.py. Add --dry-run to locate and highlight without ever placing an order.

Timing vs the backtest

The registered settings were chosen on one clock, and the live runner uses the same clock: the same decision times, look-backs and fill delay. It warns at startup if any of them is changed. Only Jev's response time and your reaction time differ, and the first is recorded on every decision (jev_ms, send_ns).

Next steps

  1. Confirm the license category with Databento, then subscribe to CME Standard and add DATABENTO_API_KEY.
  2. Parity check passes on all 15 days (done 2026-10-02; rerun after any engine change).
  3. Rehearse once at --speed 60, then run one live session with --no-jev to check the feed and recording, then a full session with Jev.
  4. Paper forward test: at least 20 sessions, settings frozen. Write the pass criteria down first, for example:
    • net P&L > 0 after costs, using live fill times (with Jev latency);
    • beats the live random baseline on total and on more than half the days;
    • worst day better than −$2,000; Jev errors/timeouts < 1% of calls.
  5. If it passes: trade MNQ, 1 contract, by hand with broker brackets; log every fill and compare with the paper P&L weekly. Stop if live results fall outside the forward-test range.
  6. Later: broker automation (on a paper/demo account first). This likely moves you to the professional non-display license.
